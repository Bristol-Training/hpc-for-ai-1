# HPC for AI part 1

Please note these training materials are under construction.

About this Course:

This course shows how to use Isambard-AI, a UK national supercomputer, to train computer vision models. You will work through a real example, training a model to spot fractures in X-ray images, and see how using more GPUs (graphics processing units) can speed up training. 

Prerequisites:

You should be comfortable with Python and have some experience with PyTorch, at the level of Introduction to AI. Some command line experience is helpful. You will need an Isambard-AI account, set up before the course; joining instructions will be sent in advance. 

What You Will Learn: 

- When and why AI projects need high-performance computing (HPC). 

- How to use Jupyter notebooks on Isambard-AI. 

- How to train an image classification model on a GPU. 

- How to spread training across several GPUs, and how this works behind the scenes. 

- Good practice for working on a shared supercomputer. 

## How the course runs

A 3-hour, hands-on session. Each attendee starts a JupyterHub session on Isambard-AI with one whole node (4 GH200s) and runs a complete notebook, `notebooks/hpc-for-ai.ipynb`. The notebook trains a YOLOv8 image classifier on the [FracAtlas](https://doi.org/10.6084/m9.figshare.22363012) X-ray dataset, first on one GPU and then on four. The slides introduce each section; the notes explain every step and have an exercise for each section.

This course is written with [Quarto](https://quarto.org), and follows the structure of the [R-Live](https://github.com/Bristol-Training/R-Live) course.

## Rendering

Install Quarto from <https://quarto.org/docs/get-started/>. No Python packages are needed to render: the notes show the course code but don't run it.

### Everything at once (recommended)

From the top-level folder, run:

```bash
python render.py
```

This creates the course pages in `resources/` and the website in `docs/`. It also checks that:

- the attendee versions contain no instructor notes, and
- every notebook code block in the notes matches a cell in `notebooks/hpc-for-ai.ipynb`.

### One output at a time

From a terminal in the `source/` folder (these write the HTML next to the `.qmd`, which git ignores; use `render.py` to update `resources/` and `docs/`):

```bash
# Instructor notes
quarto render hpc-ai-notes.qmd

# Attendee notes
quarto render hpc-ai-notes.qmd -M attendee:true --output hpc-ai-notes-attendee.html

# Slides
quarto render hpc-ai-slides.qmd
```

### Live preview while editing

From the `source/` folder:

```bash
quarto preview hpc-ai-notes.qmd     # instructor view
quarto preview hpc-ai-slides.qmd
```

## Publishing the website (GitHub Pages)

`render.py` builds the website into `docs/`:

| File | What it is |
|---|---|
| `docs/index.html` | The landing page: a short intro, the embedded slides, links to materials, then the attendee notes |
| `docs/slides.html` | Copy of `resources/hpc-ai-slides.html` (embedded on the landing page and opened full screen from it) |
| `docs/instructor.html` | Copy of `resources/hpc-ai-notes.html` |

The landing-page block lives at the top of `source/hpc-ai-notes.qmd`, inside `::: {.content-visible when-meta="site"}`, so it only appears in the website build.

To publish:

1. Run `python render.py`.
2. Commit and push, including the `docs/` folder.
3. One-time setup on GitHub: **Settings → Pages → Build and deployment → Deploy from a branch**, then pick `main` and `/docs`.

The site appears at `https://bristol-training.github.io/hpc-for-ai-1/` a minute or two after each push. GitHub Pages sites are public, so anyone with the link can read the instructor version too.

## Editing the notes

The notes follow the house style of the existing JGI courses:

```markdown
::: {#exerciseN .callout-note icon=false title='Exercise'}
The exercise (one at the end of each section).
:::

::: {#answerN .callout-caution icon=false title='Answer' collapse="true"}
The answer (collapsed by default).
:::

::: {#keypointsN .callout-tip icon=false title='Key points'}
Important concepts.
:::
```

### Adding instructor-only content

Wrap anything that attendees should **not** see in a `content-hidden` block. It shows in the instructor version and is removed from the attendee version:

```markdown
::: {.content-hidden when-meta="attendee"}
::: {.callout-important icon=false title='Instructor notes'}
**Live demo:** ...

**Pitfalls:** ...
:::
:::
```

Keep the title `Instructor notes`: `render.py` searches for it to check that nothing has leaked into the attendee copy.

### Keeping the notes and notebook in step

Code blocks in the notes headed `filename="hpc-for-ai.ipynb"` are exact copies of cells in `notebooks/hpc-for-ai.ipynb`. If you change one, change the other: `render.py` stops with an error if they don't match. Code in exercise answers and in the slides is not checked, so you can shorten it there.

Save the notebook **without outputs** before committing (in JupyterLab: *Edit → Clear Outputs of All Cells*), or install [nbstripout](https://pypi.org/project/nbstripout/) as in the [intro-to-ai](https://github.com/Bristol-Training/intro-to-ai) course.

## Setting up Isambard-AI for a course

See the **Instructor setup** section at the end of the instructor notes. In short:

1. The course runs in the training project, using the `interactive` reservation (no course reservation). Check with BriCS how many attendees can have a whole node at once.
2. Over SSH on a **login node** (the compute nodes have no internet), build the course kernel with `setup/build-environment.sh`, and put the FracAtlas dataset, the `yolov8n-cls.pt` weights and the notebook in the project folder.
3. Do a full dry run in JupyterHub and fill in the `TODO`s in the notes and notebook.
